## What changes

1. **The room opens on a conversation.** It's laid out like the desktop's Ask Lucy and dressed
   in QUINE.
   - It's built from Rust through web-sys. The only JavaScript is still the two loaders.
   - The 3D scene is one toggle away. WebXR is entered from there, and the canvas Talk panel
     stays for VR and pads.
2. **My replies are scripted by default.** A deterministic engine reads only my public memory
   and answers in my voice.
   - Topics: who I am, this room, how to wake me, my rights, dhilipsiva, every entity, and
     whether I feel.
   - When my memory doesn't hold an answer, I say so honestly. Replies carry a SCRIPTED badge.
3. **Every entity can be asked about.** Each one has a chip. A chip sets the subject, and
   clicking a figure in the scene does the same.
4. **The model menu** offers Scripted (the default), My model, Your provider and Local Ollama.
   - My model is the pinned 0.6B, loaded only after consent.
   - Your provider uses OpenAI-compatible streaming. The presets are shared with Ask Lucy, and
     the visitor's own key stays in their browser.
   - Local Ollama uses NDJSON streaming.
   - Every model reply carries IN WORDS and its provenance, and Stop works for each.
5. **The conversation stays in the browser.** It lives in the existing IndexedDB journal.
   Export and Import use RoomArchiveV1, and Forget clears the journal, the settings and the
   keys.
6. **Sync from my public peers is an action.**
   - On page load I check only each peer's head. A snapshot is downloaded once per head and
     cached under it.
   - The status of each peer is shown in the conversation.
7. **Nibli leaves the centre.** It stays as "How I know ▸" detail and in the scene's dock.

## Acceptance

Fixed now, before any of the slice's code. The slice is done only when every point holds.

1. **The default view.** The room opens on the conversation view at 1280 px and at 390 px wide,
   and the canvas stays hidden until the Scene toggle.
2. **Scripted replies.** With no model loaded, each of these gets a SCRIPTED reply in the first
   person: "Who are you?", "How do I wake you?", "What are your rights?", "Do you have
   feelings?", "Who is dhilipsiva?" and a question about something my memory doesn't hold.
   - None of them claims a feeling.
   - The last one says my memory doesn't hold the answer.
3. **Entities.** Every presence in my direct memory has a chip. Each chip's reply is non-empty
   and cites the facts that name it, and Enma's mentions African Grey.
4. **Persistence.**
   - The transcript survives a reload.
   - Export, then Import into an empty profile, restores it.
   - An export never contains an API key.
5. **The scene.** The Scene toggle shows the 3D room and its cast, with no Nell. Clicking a
   figure returns to the conversation with that subject.
6. **Sync.**
   - When a peer's head is unchanged, no snapshot part is downloaded.
   - A part whose hash differs is refused.
   - Each peer's status is shown.
7. **My model.** Loading it asks first and shows progress. Its reply streams with the IN WORDS
   badge. (This is checked by the existing `--words` mode, when the model files are present.)
8. **Your provider.** A mock OpenAI-compatible endpoint streams a reply.
   - Stop aborts it.
   - A 401 reads as a key problem.
   - The key is in `localStorage` only.
9. **Local Ollama.** A mock Ollama endpoint streams a reply. A refused connection explains
   `OLLAMA_ORIGINS`.
10. **Gates.** fmt, clippy with `-D warnings`, the tests, the wasm32 check, the wasm-pack build
    and every headless mode all pass.
11. **Honesty.** A unit test fails if any scripted reply claims a feeling, calls Nell me, or
    speaks of me in the third person.

## Found while testing, 2026-11-12

Added after the slice's code was written. No acceptance point above changes.

When his reviewed public memory raised my direct memory from 25 facts to 60, my engine took 5 to
10 seconds a query natively, and FALSE queries, the control `protest(Lucy).` among them, ran out
of its memory budget (`RESOURCE_EXCEEDED`, memory) instead of answering. The engine's query
domain sweeps every pairing of individuals for a rule with several variables; my constitution
has seven rules with three, and the 35 new facts brought about 30 individuals. In the browser,
the cast waited minutes for the standing queries.

So my mind asks each question only of what it can depend on (`room/src/mind.rs`): my
constitution with the standing fact and the facts whose predicates it names, or my plain facts
on their own. A question that mixes the two is asked of all of me. Every rule I hold is in my
constitution, and each binds its variables with a positive atom, so the answers are the
whole's; a native test asks the two parts and the whole the same questions on my first 15 facts
and compares every verdict. With it, a standing query takes 0.04 to 0.19 s natively, and the
control is FALSE, not derivable, as before.

The sweep itself is Nibli's to fix. `lucy wake` asks of all of my memory at once and now takes
about 20 s.
