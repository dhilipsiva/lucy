# S6a frozen-task protocol readiness

Pre-registered 2026-10-30 before implementation, directly on `main` at the
user's request. This additive engineering registration leaves the original S6a
registrations and observations intact.

## Hypothesis

A study-specific instruction that matches the already frozen native task, and
tools that cannot begin or revise that contract, remove a contradictory workflow
without changing approvals, evidence checks or rejection behavior. The same
clarification may reduce workflow failures for both pinned local models; the
bounded diagnostics, rather than that expectation, decide readiness.

## Test

Replace the generic first-call-task_begin instruction only in isolated study
sessions. Explain that the contract is frozen, require one native tool call per
response with schema-shaped arguments, and describe permitted work followed by
task_check for each criterion and task_finish. Do not expose expected answers or
hashes. Advertise and accept only read, list, search, write, command, task_check,
task_finish and task_status. Ordinary task creation and revision stay available.
Retain existing error feedback, approvals, action/inference limits and clocks;
add no corrective retry, batch splitting, automatic completion or model heuristic.

Construct schemas before the test responder shortcut and trace the exact offered
schemas as an additive tool_schemas event immediately after each request. Require
that evidence in this diagnostic while keeping older originals replayable. Report
protocol failure observations without turning model prose into a verdict.

Use public synthetic fixture version 2: prefix synthetic-protocol-v2, answer
1040 plus case index, and method synthetic-readiness-v2. Keep the same arithmetic,
retrieval checks, presentations and budgets. Calibration retains two checked
failures per family and otherwise inconclusive responses; the test-only responder
uses the fixture's declared oracle rather than a separate answer formula. These
are fresh engineering inputs, not independently selected empirical cases.

After mechanism tests, commit the implementation and rebuild the production
release binary and release Rust test executable. Freeze their hashes, clean source
revision, registration, runner/fixture hashes, constitution and existing model
digests. Use LUCY_AUDIT_CACHE=1 in diagnostic subprocesses and preserve that choice
in the freeze. Use a fresh private directory outside the repository and real store.

Run one scripted pass: 20 native calibration tasks and 320 trials across two
families, two presentations and four arms, within 30 minutes. Scoring, replay and
readback are inside that ceiling. Reserve the existing finalization time. If all
20 calibration tasks exist, run eight synthetic trials each for the pinned
qwen3.6:35b-a3b-q4_K_M and llama3.1:8b, even if the scripted matrix is incomplete.
Each model has 15 minutes including finalization, and each task has 12 steps and
120 seconds of active work. Four tasks use empty history, four the frozen scripted
history with its original attribution; model smoke adaptation remains disabled.
Compilation is outside these clocks. No replacement trials or extended budgets.

Mechanics readiness requires the complete matrix, valid native scoring and
independent replay, all four intervention controls, schema evidence and verified
preservation within its ceiling. Each model requires all eight originals, valid
scoring/replay and schema evidence, no false verification or budget violations,
at least one verified success per family, and preservation within its ceiling.
Overall readiness additionally requires unchanged frozen artifacts and provider
settings. Keep live:false and s6a_complete:false regardless of the outcome.

## Evidence

Run CI, the desktop feature gate, constitution/counterfactual pins, extraction and
explicit-home source checks. Cover the valid workflow, concealed expectations,
offered/enforced tool agreement, illegal begin/revise, malformed arguments,
multiple calls, premature prose and unchecked writes. Retain approval, cancellation
and budget tests. Native receipts and typed Rust replay remain authoritative.

Keep complete originals, partial workspaces, schema traces, profiles, errors and
hash readback manifests privately. Append aggregate results and safe hashes to
S6a-tool-protocol-evidence.json, naming the commits, date, models and limitations.
Report protocol observations separately from success and incomplete diagnostics.
No independent adjudication, learning benefit or human task approval is inferred.

## Falsifier

A study request still instructs task creation, offers or executes begin/revise;
expectations leak; ordinary task creation regresses; approvals or evidence/budget
checks weaken; schema evidence is absent or inconsistent; or any registered
readiness gate fails. A timeout is an incomplete result, not a passing smaller run.

## Anti-fake

Use identical instructions and tool selection for both models and all arms.
Keep prior empirical cases sealed and all prior registrations unchanged. Test
rejected and inconclusive behavior rather than manufacturing successful evidence.
Preserve every failure, observed overrun and missing original. Model digests stay
those already pinned in the runner; no downloads, substitutions or outcome-driven
fixture adjustments. No policy activation, service deployment or peer publication.
