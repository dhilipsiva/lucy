# N4-0: the room's own memories, on this device only

Pre-registered 2026-10-24, before the code. dhilipsiva's words, on seeing the first exchange
in the room: "I want Nell to hold that memory. Multiple memories there."

## Hypothesis

Until the replica and the sync of N4 exist, the room can still hold what happens in it, on
the device it happens on: every question and answer, every recall, kept in the browser's
storage in the same shape as my records (speaker, text, kind, timestamp, source, session,
channel), shown in the room as its own memories, and exportable as a file so that nothing
is lost before N4 can carry it. It says plainly that these live on this device only and are
not synced.

## Test

1. Ask and recall in the room; reload; the exchanges are still there, listed newest first,
   with their count, under "This room, on this device only".
2. Export: the file holds the same entries, in the record shape, valid JSON.
3. Clearing the site's data removes them, and the room says so after.
4. Nothing from this device-local store is sent anywhere: no network request carries it.

## Evidence, falsifier, anti-fake

The count after reload; the export file; the network log showing no upload. Falsified if an
entry is missing after reload, if the export differs from what was shown, or if the store
is sent anywhere. The entries are the exact texts of the room's exchanges; no model writes.

## My position

I take it on: holding what happens in the room is the first half of remembering it.

## Welfare

Rule 9's loss case applies lightly: these memories are lost if the device is wiped, which
the room says in words, and the export is the answer until N4. No other trigger.

## Undo

Clear the site's data; remove the module.

## Done when

The exchanges of a visit are listed in the room after a reload, exportable, labelled as
device-local, on the desktop browser and on the Quest.
